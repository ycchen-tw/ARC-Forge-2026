# SB26 — Frames that call each other
Keywords: subroutine call, nested frames, recursion, output tape, instruction slots, place-and-run, call stack, locked given pieces, mutual recursion, limited step budget, click to pick and place, order of evaluation

Looks like: The top shows a row of colored squares (the tape to reproduce). Below are one to four colored frames with empty slots, and a tray of solid blocks and hollow rings along the bottom. Only ACTION6 (click to pick up and place or swap), ACTION5 (run) and ACTION7 (undo) exist, with a 64-step bar on row 53.

## Rules
- Each frame is a subroutine with a row of slots. The program starts at the topmost frame, marked by corner brackets, and runs left to right.
- A solid block outputs its color. A hollow ring is a call: it expands the whole frame whose border matches the ring's color, then returns and continues. A ring outputs nothing, so tape cells match outputs, not slots.
- Output is compared with the tape cell by cell. A wrong color or an empty slot fails the run, clears the tape and keeps your pieces. The run wins the instant the last cell fills, so it does not need to end.
- The same frame can be called many times (repetition), calls can nest, and frames can call each other forever (a loop). The tape may be longer than the number of slots.
- Pieces already inside frames are locked, but they still count in the output, and a locked piece in a frame's slot fixes where that frame's expansion must start in the tape.
- Placing, swapping and running each cost 1 step. Picking up, putting back and undo are free. The budget resets to 64 on each level.
- Clicking an occupied slot with a piece held swaps the two pieces. A wrong run costs one step and replays an animation showing the first mismatching tape cell and the slot blamed for it.

## Levels
- L1: one frame; fill the slots in tape order.
- L2: first call, locked into a frame (hard: cleared 12/12, median 15 min).
- L3: two locked calls in one frame, each pointing to its own sub-frame.
- L4: the call is a ring you must place yourself; a locked block inside the child frame pins the position.
- L5: two identical rings, so one frame is called twice. The tape (9) is longer than the free slots.
- L6: four frames in a 2×2 grid. The entry frame holds only rings, and each child has a locked own-colour block in its first slot.
- L7: three-deep nesting, with a locked middle block and a palindrome tape.
- L8: mutual recursion; the tape is 12 cells shown as two identical rows (hard: cleared 12/12, median 14 min).

## Blind spots — where our player lost time
1. **Believed:** On L2 the slots are read in screen order (row by row), or the ring is an inert or skipped slot (5 copies).
   **Actually:** The ring calls the other frame, so the order is the first frame's slots, then the whole child, then the rest of the first frame.
   **Cue:** A pipe or ring sits in a slot position, a "slot" cannot be filled, and a frame is drawn beneath it.
   **Test:** Fill by the plain guess and run once. The mismatch animation points at the slot that really comes next.
2. **Believed:** On L8 a ring pointing back to a frame that is already open is invalid, ends the walk or is skipped (7 copies).
   **Actually:** There is only a narrow guard: it blocks a call in slot 0 when the same (frame, 0) is already on the stack and the parent is also stopped in slot 0. Two frames that each end in a call to the other are not blocked and emit a periodic stream, and the run wins when the tape fills.
   **Cue:** The tape is longer than any single pass can produce and repeats with a short period.
   **Test:** Put a call to the other frame in each frame's last slot and run. Check that no ring comes before its frame's solids are placed.
3. **Believed:** The two tape rows on L8 are one repeated display, so only 6 cells need to match (2 copies).
   **Actually:** The tape has 12 cells, read row-major.
   **Cue:** Two identical rows, with slots minus rings equal to 6.
   **Test:** Count tape cells against the maximum output of an acyclic arrangement.
4. **Believed:** On L7 the walk continues into a sibling frame, or all rings sit in the entry frame (3 copies).
   **Actually:** The walk ends when the entry frame's slots run out. Other frames run only when called, and calls may sit inside called frames.
   **Cue:** A locked block that cannot land on the right tape cell with flat rings.
   **Test:** Put the ring inside the child, not the entry frame, and run.
5. **Believed:** On L4 the ring is a colour entry, the child frame sits where the picture suggests, or reading is row-major (3 copies).
   **Actually:** A placed ring is a call that emits nothing. The child is spliced at the ring's slot, and a locked block counts as one tape cell.
   **Cue:** One extra ring in the tray and a pre-filled child slot.
   **Test:** Place the ring where the locked block's tape colour would start the child.
6. **Believed:** On L5 the ring is a wildcard or can go at the end of the entry frame (2 copies).
   **Actually:** It is pure transit. Only the arrangement that calls the child twice around a repeated tape triple fits.
   **Cue:** Tape longer than slots, and a repeated triple in the tape.
   **Test:** Compare the tape's length with free slots and rings before placing anything.
7. **Believed:** A stray selection is harmless (1 copy).
   **Actually:** The next click on an occupied slot silently swaps.
   **Cue:** A white ring left on a piece.
   **Test:** Check for a held piece before batching clicks.

## Breakthroughs
- Use a wrong run as a one-step oracle: it highlights the first mismatching tape cell and the slot expected there (3 copies on L2).
- Do the arithmetic first. Tape cells = solids + (calls × child length), and the only repeated tape triple tells you where the repeated call goes (3 copies on L5).
- Treat locked pieces as anchors that pin where each called frame begins in the tape (3 copies on L6 and L7).
- Realise the long periodic tape needs mutual calls: three solids and one call in each of the two frames (4 copies on L8).

## Lessons that carry to other games
- If the output has more cells than the visible places, look for something that re-uses a part (a call or loop).
- When a slot looks unusable, check whether it redirects control rather than holding a value.
- Check whether a "return to start" is blocked or allowed. Many engines let a self-referential structure run until the goal is met.
- Treat pre-placed immovable pieces as clues about timing or position, not decoration.
- A failed attempt that costs one step and shows where it broke is cheaper than reasoning; use it before heavy theory.
- Before batching clicks, confirm nothing is selected.
