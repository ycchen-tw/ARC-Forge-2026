# TN36 — Binary instruction tape steers a block

Keywords: bit-coded instructions, program tape, click to toggle bits, run button, demonstration machine, hint panel, checkpoint, retractable hazard, timed hazard, scale/rotate/recolor, walls, multi-run, irregular encoding

Looks like: A "machine" with a small board, a block, and a U-shaped target frame. Below it is a tape of columns made of small bars and stems, plus a round run button. All input is clicks on tape cells, the run button, or demo-selector buttons. From level 2 on, a second machine on the left runs read-only demo programs when you click its selector buttons. A progress bar along the top row shrinks one cell per click.

## Rules
- Each tape column is ONE 6-bit instruction (value 0–63). The six cells are the bits, top = least significant. Clicking a cell flips that bit.
- A run resets the block to its start, then executes one column per frame, left to right. Unused columns are 0 (no-op).
- Clearing needs the final block position, scale, rotation and color to all equal the frame's requirements. The frame's color is the required block color, and its opening shows the required rotation. A failed run puts everything back; only the click counter moves.
- The instruction table is irregular. Up is 33. Left is 1 or 34. Right is 2. Down is 3. Codes 10/12 move two cells and check only the destination, so they hop over walls. Rotation is 5/6/7/16, scale +/- is 8/9, and recolor is 14/15/63.
- The demo machine shows the real mapping. Its displayed tape is the program for the demo it just played. The demo block stays at its end point.
- Walls roll back any move or scale change that would overlap them. The board has no edge: a block can leave it and come back.
- Dotted checkpoint sockets: if a run ends with the block on one, its whole pose (position, rotation, scale, color) becomes the next run's start. Hence multi-run solutions.
- Retractable spikes switch state after the third instruction. They are retracted for instructions 1–3 and extended for 4–6, and any contact kills the block. The click bar slows to one cell per 2 clicks in levels 6–7.

## Levels
- L1: 5 columns of 2 bits. Press run to learn what the pre-set tape does (14 min median).
- L2: 6-bit columns plus the first demo machine. Up is a combination of two non-adjacent bits (hard: cleared 12/14, median 76 min, 2 stuck copies at 160 and 105 min).
- L3: 6 columns, a wall with one gap, four demos giving the four directions (cleared 12/12, median 29 min).
- L4: scaling; the block must shrink to fit a one-cell wall gap (15 min).
- L5: rotate and recolor; the frame is a different color and larger, so the block must grow after passing the gap (cleared 11/12, 15 min).
- L6: maze plus three checkpoint sockets; needs two or three runs, and one wall is fake (hard: cleared 10/11, median 31 min).
- L7: two spikes on one row plus checkpoints (hard: cleared 9/10, median 42 min).

## Blind spots — where our player lost time
1. **Believed:** the L2 tape is rows of independent switches, so single keys can be tested one at a time ("row 3 alone = nothing", "the machine has no UP"). Two copies never moved the block up and got stuck.
   **Actually:** each column is one 6-bit number. Up (33) needs the first and last bits together, and either alone does nothing.
   **Cue:** after a demo button is pressed, the left machine's tape shows lit cells in two separated rows while its block moves up.
   **Test:** copy the demo's lit cells exactly onto your tape and run once.
2. **Believed:** the tape length is the same as in the previous level, so L3 "needs a multi-cell move". One copy missed the sixth column entirely.
   **Actually:** L3 onward has six columns, and the run button moves between levels.
   **Cue:** the run animation's highlight visits more columns than you have been using.
   **Test:** count the columns and click spots on every new level before planning.
3. **Believed:** a pixel-perfect fit of block in frame wins (L5), or "a solid rectangle of one color" is the win test.
   **Actually:** the color must also match, and the frame's color is the required color. Six copies ran a perfect fit that reverted.
   **Cue:** the frame is a different color from the block, and a demo button shows a recolor program.
   **Test:** when a perfect fit still reverts, run a recolor column (value 63) before it.
4. **Believed:** every run snaps back unless it clears the level, so a 9–14-move route in 6 columns looked impossible (hours lost in L6).
   **Actually:** ending a run on a dotted checkpoint socket keeps the pose, so you chain runs.
   **Cue:** dotted 4×4 patches scattered through a maze, and a route longer than the tape.
   **Test:** end one run on a patch and compare the board before and after.
5. **Believed:** the L7 danger row is a reactive beam or a gate, so crossing it was "impossible". Copies also hunted a vertical two-cell hop for ~200 actions. Every copy first died by walking straight up.
   **Actually:** the spikes extend by a global timer after instruction 3, whatever the block does. You can stand in the row during instructions 1–2 if you have left by the end of instruction 3.
   **Cue:** the hazard appears at the same frame even when the block is far away.
   **Test:** run an empty tape and watch which frame the hazard appears. Then start a run from a checkpoint one row below the hazard.
6. **Believed:** hand-read maps (an off-white tile treated as wall, shifted columns) showed the level as unsolvable.
   **Actually:** the misreads were the player's, not the level's. Test and map reading must be done programmatically.
   **Cue:** "unsolvable" conclusions that depend on an eyeballed grid.
   **Test:** classify every cell by code and compare with one observed move.
7. **Believed:** scaling up is always allowed.
   **Actually:** an enlargement that would overlap a wall is rolled back silently. Pass narrow gaps small, then grow.
   **Cue:** the block stays small after a scale-up instruction.
   **Test:** put the scale-up instruction after the wall crossing.

## Breakthroughs
- L2: copies that cleared pressed the demo button and copied the left tape's lit cells onto the right tape. Twelve copies cleared; each did it after their individual-key tests failed.
- Treating the six cells as binary digits and enumerating the codes found rotation, recolor, two-cell hops (which jump walls), and showed that no two-cell vertical move exists.
- L6–L7: parking on checkpoints and splitting the route into runs. L7 additionally crossed the hazard row in the first two instructions, starting from a checkpoint a row below. One copy instead left the board and came back.
- L5: order matters — rotate, pass the gap small, then grow, then recolor.

## Lessons that carry to other games
- If a panel looks like independent switches, test combinations and copy the demonstrator's displayed state exactly before probing single elements.
- Re-count the controls and re-locate the buttons on every level; they can change.
- A perfect geometric fit that still reverts points to an unchecked attribute (color, rotation, scale); compare every attribute of the target.
- If every attempt silently resets, look for a marked spot where state persists, and test one attempt ending on it.
- For a hazard that seems to react, run a null action and check whether it is a fixed timer.
- Before hunting an "impossible" capability for a long time, re-read the map programmatically and recheck what counts as a wall.
- A scale or size change can be refused where a move is not; check for overlap after each size change.
