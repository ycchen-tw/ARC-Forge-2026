**The action limit is 100 per level, with 99 usable actions in practice**. At the start of `step()`, `self._action_count >= 100` immediately triggers lose (the counter has already incremented when the action is sent, so sending action 100 immediately loses).
Official `arcengine` resets `_action_count` to 0 in `set_level` on every level entry (confirmed by inspecting official 0.9.3 source on 2026-10-20).
(An earlier draft of this page said “shared across the whole game,” based on the reconstructed engine's then-cumulative behavior across levels; the reconstructed engine was changed to reset per level on 2026-09-12.
The human baselines total 171 under the current metric / 136 under the old metric; the engine code above determines whether each level resets.)

**Layout**: The **target pattern** (10×10) is at the upper left; the **canvas** (10×10, initially all color 0) is at the center. There are 8 tool positions around the canvas (4 orthogonal positions above/below/left/right + 4 diagonal corner positions). The **palette** is in the top row (the initially held color is purple, 15; color 0 is also on the palette, so “leave unpainted” and “paint 0” are equivalent).

**Core rule**: Use large brushes to paint areas of the canvas until it matches the target. Painting **overwrites**: the entire later stroke covers earlier paint. The actual puzzle is therefore **stroke order**: lay a base, then carve out shapes layer by layer.

**Action mapping**

- `ACTION1-4` (up/down/left/right respectively): move selection between the 8 tool positions, arranged on a 3×3 layout (the center is the canvas).
  ⚠️ An earlier description, “skip the center,” was ambiguous: in fact, you **cannot enter or cross the center**. If the computed destination is the center, the function returns without moving (`nqhfiooufi()` has `if (row, col) == (1, 1): return`); clamping at a boundary likewise leaves the tool in place. The 8 positions thus form a **ring**: moving from “top” to “bottom” takes at least 4 moves.
  ⚠️ Also, **only the currently selected tool is drawn**; the other 7 positions are empty. That tool is recolored to the **current color** (`gpfahgizbk()` / `elltphoitr()` / `azhynfjdiz()` remove all `ActiveBasket` objects on each position change, replace just one, and apply `color_remap(15, current_color)` (`current_color` is a descriptive placeholder for the current color)). Thus “8 tool positions around the canvas” means 8 **positions**, not 8 visible brushes.
- `ACTION5`: **paint a stroke**. The current tool sweeps into the canvas and returns (7 animation ticks each way; an ordinary stroke returns 15 frames, with the whole sequence counting as one action):
  - An **orthogonal brush** paints **half** the canvas (upper/lower/left/right half, 5×10 or 10×5).
  - A **corner brush** paints a **triangle** (one of four triangles cut along a diagonal), and all four triangles **include the diagonal itself** (`rtjwayrycq()` uses slices `pixels[i, 0:i+1]`, `pixels[i, i:10]`, `pixels[i, 9-i:10]`, `pixels[i, 0:10-i]`, all including their endpoints).
- `ACTION6(x,y)`:
  - Click a palette swatch → change the current color (the indicator below moves beneath that swatch).
  - Click the **small brush** → paint a centered **edge strip** along the canvas edge, more precise than the large brush.
    ⚠️ Previously described simply as “3×4”: the top/bottom strips are **3 rows × 4 columns** (rows 0-2 / 7-9 × cols 3-6), while left/right strips are **4 rows × 3 columns** (rows 3-6 × cols 0-2 / 7-9) (`coublenfir()`).
    ⚠️ There is also **only one small brush at a time**, beside the **currently selected orthogonal tool position**; it disappears entirely at a diagonal position (`eanmnpxtyi()` first removes all small brushes, then `if slot not in [0, 2, 4, 6]: return`, before placing one using its offset table). “Appears only at the 4 orthogonal positions” does not mean four permanent brushes: to use a side's small brush, **first move the large tool to that side**.

**Victory check**: The canvas is compared cell by cell to the target, but **the 20 cells on the two diagonals are ignored; only the other 80 are compared** (`wvrremwltt()` sets `[i, i]` and `[i, 9-i]` to False in the mask). Complementary diagonal brushes both paint the diagonal, but the rules do not require any final color there. Victory is checked only when a large- or small-brush animation finishes; movement and color changes do not trigger it.

**Charging and reset**: Each direction action that stays in place, reselecting the same color, clicking blank space/the canvas/a large brush, and effective painting all count as 1 action. Large brushes cannot be selected by clicking; direction actions are required. Action 100 loses before any effect or animation begins, so a final stroke cannot win at that limit. There is no Undo. Changing levels resets the canvas to 0, tool to the top position, current color to 15, and action count to 0; the small brush is rebuilt according to the level settings. Position/color/canvas/target are all visible, with no hidden target. Official `RESET` restarts the current level if an action has already been sent in it; at action count 0 or after completing the game, it returns to level 1 (environment variable `ONLY_RESET_LEVELS=true` restricts RESET to the current level before game completion).

**Level by level** (all screens 64×64, canvas always 10×10)

The stroke orders below have been verified by cell-by-cell simulation: painting in this order reproduces the official target sprite (level 5 differs in only
5 main-diagonal cells, which are excluded from comparison anyway). **Fewest strokes does not mean fewest actions**: each stroke also requires paying to
move around the tool ring and change color. The last column therefore lists existing measured routes separately; no global-optimality claim is made here.

⚠️ The previous version said level 5 “uses no half-canvas stroke anywhere.” That describes **that particular route**, not the level:
a different stroke order (starting with upper half 9) also clears it and uses fewer actions.

**How the stroke order is derived**: Painting overwrites whole areas; a cell's final color is determined only by the last stroke covering it. The easiest method is therefore
to peel strokes backward from the last: **every compared cell** covered by the last stroke (including already-correct cells, which it will overwrite too)
must have the same target color, or one stroke cannot produce it. Once confirmed, those cells no longer constrain earlier strokes; remove them
and consider the second-to-last stroke. **The easiest mistake is checking only that “the still-incorrect cells have the same color.”** That admits false solutions such as
repainting an entire large triangle in a corner's color, which actually ruins the image. All 6 levels can be solved within 4 strokes.
