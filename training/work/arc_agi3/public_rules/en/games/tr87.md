### Layout

The 64×64 screen has two regions: **upper background color 2** (camera background), **lower background color 3** (a 64×32 image clipped downward).
The boundary y in L1–L6 is **34/34/34/37/38/41**, not a fixed halfway split.
Thus the row immediately after “the last row still containing color 2” is the boundary; it can be measured directly from pixels.

- **Upper region = rule table**: Several rewrite rules, each written as “left symbol string ─ right symbol string.”
- **Lower region = two strings**: The upper row is the **source string** (always immutable), the lower row the **target string**.

**Symbol appearance**: Each symbol is a 7×7 card. The outer border has the card color; the region inset by 1 px is 5×5 and contains the pattern,
whose strokes always use color 5. The card color identifies the alphabet: **10=A, 7=B, 11=C**. Card color **always equals**
the symbol's alphabet (checked across all 6 levels, with no exceptions). Each alphabet has 7 patterns, numbered 1..7.

**At initialization a fixed-seed PRNG rotates each pattern by 0/90/180/270**. Rotation affects no judgment and is purely perceptual interference.
Measured: after normalizing each of the 21 5×5 patterns to “the lexicographically smallest of its four rotations,” they are **all distinct**,
even across alphabets—once rotation is factored out, each is uniquely identifiable without other clues.

**Layout geometry** (the solver uses these constants to segment the screen)

| Quantity | Value |
|---|---|
| Card | 7×7; 5×5 pattern at card top-left +(1,1) |
| Spacing between adjacent cards on one side | 7 (touching, appearing as one continuous same-color strip) |
| Spacing between the two cards flanking the equals sign | 10 (3 empty cells between them) |
| Spacing between two rules on the same row | ≥ 12 |
| Rule order | By (row y, left-side starting x); **two rules can appear side by side on one row** |

**Measured correction｜The equals sign is a horizontal line, not a vertical line**: The original description, “the vertical line in the middle is the equals sign,” was wrong.
It is actually an 11×1 **horizontal** line sprite (color 3, layer −2), with both ends covered by cards.
Only its middle **3 pixels** are visible, on the central row of the cards (card row y+3).
Thus “a 3-cell gap between cards, with color 3 on its middle row” means those groups form the two sides of one rule.

**Cursor**: A pair of upper/lower brackets (color 0), each occupying 2 rows—a solid line and two endpoints.
The upper solid line is 3 rows above the card top, equivalently 4 rows above the inner 5×5 pattern; its endpoints are 2 rows above the card top. Its width is `5 + 7×(number of symbols enclosed − 1)`.
In **nonterminal resting frames outside the success animation**, only the cursor uses color 0, so scanning color 0 locates it. Success animation and the final WIN frame also use color 0 for symbols and rule overlays.

### Core judgment

Rewrite the source string using the rules; the result must match the target string. Scanning is greedy:
starting at the beginning of the source, find the **first** rule, in **rule-table order**, whose left side matches at the current position. Consume it,
append its right side (possibly after one further translation) to the output, require the corresponding target substring to match exactly, and continue.

**Measured correction｜Three easily missed details**

1. **If the selected rule's right side does not match the target, this answer check immediately returns False** (editing can continue; this is not `lose`). It does not backtrack to another rule.
   ⇒ The chosen rule depends entirely on the **source string + rule table**, independently of the target.
   (This makes search unnecessary for levels without `alter_rules`: the required target string is uniquely computable.)
2. **Success occurs once the source is consumed; any remaining target suffix is ignored**. If output is shorter than the target, the extra cells may contain anything.
3. **Judgment runs only after ACTION1/ACTION2 (pattern editing)**; moving the cursor does not trigger it.
   ⇒ Even if the initial board is already an answer, an edit must trigger the check; changing something away and back is one option.

After success, an animation plays (symbols change color one by one through `5→8→14→15→6→9→12→0`, and 9×9 color-0 squares overlay matching rules).
The entire animation finishes within **the same action**. In L1–L5 its last frame shows the next level; L6 instead returns **WIN**, retaining white symbols and rule overlays, with no next-level frame.

### Action mapping

- `ACTION3` / `ACTION4`: Move the cursor left / right (**cyclic modulo the number of selectable groups**, wrapping around).
- `ACTION1` / `ACTION2`: Cycle the enclosed symbols to the **previous / next** pattern number (mod 7).
  Only the number changes; **the alphabet (card-border color) stays fixed**—the border therefore fixes what each cell can become.

### Three difficulty flags (in level data, invisible on screen)

| flag | Effect |
|---|---|
| `double_translation` | **Compose two rules**: use a rule's right side as another rule's left side, then take the latter's right side as the final result |
| `alter_rules` | **Edit the rules themselves**, replacing the cursor's entire selection domain |
| `tree_translation` | Expand **each individual symbol** on a rule's right side into another rule's right side (tree expansion) |

**`alter_rules` (already corrected in the original text; two further measured details follow)**
The cursor domain is not “expanded”; it is **entirely replaced**: from the target string to “both sides of every rule”
(the modulo domain changes from `ztgmtnnufb` to `[set for rule in cifzvbcuwqe for set in rule]`).
The target string is now given and immutable. In addition:

- **Measured addition**: The cursor encloses **one entire side** at a time. ACTION1/2 cycles **all symbols on that side together** by one step.
  Relative relationships within a side (differences between symbol numbers) are therefore **invariant**; the player can only rotate the whole group.
- **Measured addition**: The initial “random shuffle” is **a random 0..6 whole-side rotations for each side**, rather than independent symbol rotations.
  The only unknowns are thus “how far to rotate each side”: 8 unknowns in level 5 and 12 in level 6.

**`double_translation` (measured additions)**
The search for the second rule uses `zip`, **comparing only up to the shorter length**—if the right side has 2 symbols and a candidate left side has 1,
matching the first symbol suffices. If no second rule connects, discard this rule and try the next.
Also, the source branch (`lonhgifaes`) that uses `tjaqvwdgkxe`-tagged sprites to make “cross-rule links”
has **no such sprites in any of the 6 levels**, so it is effectively dead code and can be ignored entirely.

**`tree_translation` (measured additions)**
During expansion, matching checks only **the first symbol on a candidate rule's left side** (`avnzkzyzox[0].name == symbol name`).
A match appends that rule's **entire right side**; if any symbol cannot expand, discard this rule and try the next.
All three flags are enabled in level 6, but the code uses `if tree_translation: ... elif double_translation: ...`,
so **tree takes precedence and double has no effect**.

### Inferring invisible flags from the screen

`alter_rules` is actually **visible**: the cursor brackets appear **above** the boundary (on rules).
When they enclose the target string in the lower half, it is off. The remaining `double` / `tree` distinction requires inference from alphabets, symbols, and subsequent edits:

Try all three semantics (direct / two-rule composition / tree expansion), checking alphabet and symbol compatibility.
“Exactly filling the target” may be a solving preference, but **is not an engine requirement and cannot uniquely identify the flag**:
`bsqsshqpox` requires only that the entire source be consumed and the generated string match a target prefix. Structural clues in existing levels are:

- Levels 1~3: Only “direct” works (composition/tree cannot find second-layer rules).
- Level 4: “Direct” produces B for target cells requiring C, so the alphabets fail to match; composition works.
  (All right sides have just 1 symbol here, so tree and composition give identical results; either interpretation works.)
- Level 5: Only “direct” has a solution; composition/tree cannot even form one connected group.
- Level 6: “Direct” is impossible (A-starting rules produce B, which can never match the C target).
  “Composition” produces 1 C per source symbol, total length 3; “tree” produces 3×2 = 6.
  **3 ≠ 6 alone cannot rule out composition**, because the target suffix is ignored. Source confirms that the actual flag is tree.
  Length alone should not be claimed to identify it uniquely, especially since tree and double are already observationally equivalent on L4's one-symbol right sides.
